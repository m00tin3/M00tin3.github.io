三次面试反思与应对

这份稿子只有三样东西：

  1. 反思 —— 每场面试我具体错在哪，对着录音里的原话看。
  2. 不会的题 —— 面试官问的、我当时答的、正确答法是什么。
  3. 应对方法 —— 答不出来怎么救、被质疑简历怎么说、表达上要改的毛病。

不写预测，不押题，只写已经发生的事，和该补的答案。

面试前 10 分钟看：最后一节「进门前速览」。

三场面试对下来

谁 面试官风格 我的问题，一句话
一面 礼芮行 项目为主，顺着简历问 讲不清：秒杀流程讲反、术语错、数据瞎报

一句话：一面丢在嘴上，二面丢在半懂，三面丢在没学。

1.2 不会的题 / 答错的题

① 秒杀系统怎么实现的

面试官问的：那你大致讲一下，你这个秒杀系统这一块。

我当时答的：先去读数据库判断库存是否剩余 → 预扣一单 → 再用 SETNX 锁住 → 数据库唯一索引兜底。
问题：顺序反了（锁应该在扣减之前，而且真正兜底的是 Lua 的原子性），而且我说的”预扣一单”和”加锁”是两件事，听起来就是没想清楚。

正确答法：分四层说——场景、演进、实现、兜底。

“场景是限时抢徽章，规模不大。徽章虽然是虚拟物品，但我给每个活动设了限量，所以它有库存，也就有超卖。这个场景要解决三件事：超卖、一人多单、抢购瞬间数据库被打爆。

实现上我走了一条演进路线，因为这条路线能说明我的思考过程：最开始是收到请求就查数据库，库存够就减一，这个在并发下肯定超卖；后来上乐观锁，更新的时候带上库存条件，能防住超卖，但所有请求还是全打到数据库；再往后把判断挪到 Redis 里用原子命令做；最后落到 Lua 脚本，这是现在的方案。

为什么最后选 Lua？这件事其实是四步：第一，查库存这个 key 在不在，不在就先用活动配置的库存数初始化；第二，读库存，小于等于零就直接返回售罄；第三，用 SETNX 写一个一人一单的标记，key 是 seckill、order、活动 ID、用户 ID 四段拼起来的，如果 key 已经存在就说明这个人抢过了，直接返回；第四，把库存减一。这四步必须一起做完，中间不能被别人插进来。我一开始试过 Redis 事务，就是 MULTI 和 EXEC，但事务里面没法做条件判断——库存不够的时候我没法提前返回。Lua 就没这个问题，而且 Lua 在单机 Redis 里是单线程执行的，执行期间不会有别的命令插进来，天然就是原子的，还只需要一次网络往返。

数据库这层我加了一道双保险：订单表上把活动 ID 和用户 ID 做成联合唯一索引。因为 Redis 重启之后一人一单的标记会丢，但数据库的唯一约束是最后一道防线，重复插入直接失败。我要诚实说，这个只能防住一人多单，防不住重启之后的超卖（Redis 把库存重新初始化成一百，之前卖出去的它不记得了），那种要靠对账任务以数据库为准回填 Redis，我项目里没做。

落库是异步的，用 Async 注解，不阻塞抢购主流程。如果写失败了，在 catch 里做补偿：把库存加回去，再把一人一单的标记删掉，让这个用户能重新抢。

数据上我只说能验证的：20 个并发实测，刚好一单成功、十九次被拦、零超卖。QPS 我没跑过压测，不报。”

② 唯一索引根据什么建的

面试官问的：唯一索引根据什么？约束的组件还是用户的组件？

我当时答的：”规章的组件还是用户的组件”——没答出来。

正确答法：活动 ID 和用户 ID 这两列，做的是联合唯一索引。
为什么偏偏是这两列：单看活动 ID，一个活动下面有很多人下过单，它不唯一；单看用户 ID，一个人参加过很多活动，也不唯一。只有把这两列放在一块，语义才是”这个人在这个活动里的那一单”，它才唯一。插入第二条的时候 MySQL 直接抛主键冲突异常，我在落库那一步接住，把这次抢购当成失败处理。

③ Bean 的生命周期

面试官问的：像 Bean 的生命周期，能讲解一下吗？

我当时答的：”首先它是要注册和扫描，并生成 BeanDefinition，然后去进行初始化、实例化，然后属性填充……”——开头还行，讲到 scan 和后面的顺序就乱了。

正确答法：按这个顺序背，一步都别跳——
注册 BeanDefinition → 实例化 → 属性填充 → Aware 回调 → BeanPostProcessor 前置处理 → init 方法 → BeanPostProcessor 后置处理 → 使用 → 销毁。
两个补充点：第一，中间 BeanPostProcessor 那两步是 AOP 能生效的位置——后置处理那一步会判断要不要生成代理对象，所以 AOP 代理是在初始化之后才有的。第二，构造器注入的循环依赖和 prototype 作用域的循环依赖解决不了，因为实例化都没完成，没机会提前暴露。

④ MySQL 能力（索引、事务）

面试官问的：你的 MySQL 能力怎么样？

我当时答的：只说了用 MyBatis Plus 生成 SQL，加上 AI 辅助——等于没答。

正确答法：分三块讲，每块都落到项目里真做过的。

  • 索引：联合索引要遵守最左前缀；能用覆盖索引就不回表；分析用 explain，重点看 type、key、rows。项目里活动订单表用活动 ID 加用户 ID 做了联合唯一索引，既做索引又保证业务约束。
  • 事务：ACID、四个隔离级别，MySQL InnoDB 默认是可重复读，靠 MVCC 加快照读、当前读加 next-key lock 解决幻读。
  • 项目落点：支付单的订单号建唯一键保幂等；金额字段全部用 decimal 不用 float（float 存小数会丢精度，钱不能这么存）；MyBatis 的 SQL 全部用 #{} 预编译，防 SQL 注入；另外在苍穹外卖那个项目里写过 MyBatis 的 XML，动态 SQL 的 if、where、foreach 都用过。

⑤ 能扛多少并发

面试官问的：你这个秒杀系统能扛多少并发？

我当时答的：”能扛住 1000 到 2000 的 kps。”——术语错（是 QPS 不是 kps），而且没有压测背书。

正确答法：不报没有实测背书的数字。
“我只做了功能层面的验证：20 个并发，1 单成功、19 次被拦、0 超卖。
我要说明一下这是功能验证不是性能验证。它验证的是逻辑对不对——会不会超卖、会不会一人多单、扣减是不是原子的，这一类问题跟并发量没关系，只要有两个线程同时进来就可能出问题，所以二十个并发足够暴露。性能验证看的是另外的东西：吞吐量、响应时间的分布、错误率，还要定位瓶颈在哪，是 Redis 的网络往返、数据库写入、还是异步线程池排队。这些必须用 JMeter 这类工具持续加压跑一段时间，再配监控看指标才敢下结论。我没有压测工具也没有监控数据，所以不报那个数字。”

⑥ AI 占比

面试官问的：这些项目写的时候，AI 在行业辅助大概占多少？

我当时答的：”它写嘛，反正我要能看懂就行。”——这是原话，也是扣分点。

正确答法：”AI 我主要用在三个地方：查 API 文档、写一些重复的模板代码、还有报错的时候帮我一起看日志。核心的逻辑都是我自己设计自己写的——比如秒杀那个 Lua 脚本、缓存的三套策略、微服务之间的接口契约、还有事务那条链路。前端页面 AI 帮得比较多，因为我对前端的定位就是能看懂、能改。后端大概七成是我自己实现的。”

⑦ 项目名要张口就来

当时的情况：介绍第二个项目时我说”嗯那个叫啥”，自己项目名想不起来。

改法：两个项目各备 1 分钟版和 3 分钟版，名字张口就来——盖楼吧（社区论坛）、今日速达（快递速送平台）。

二、二面 · 上海熙宽信息技术

这家是面向政府单位的信息化公司。面试官比较温和，全程给了很多提示和台阶（我低血糖发作时还让我慢慢来）。但下面六处还是掉了分。

2.1 反思：这场我错在哪

2.2 不会的题 / 答错的题

① Spring MVC 的 Bean 是单例还是多例

面试官问的：那你觉得 Spring MVC 中的 Bean 是单例的还是多例的？

我当时答的：”Spring MVC 其实好像是多实例的吧……因为它是一个第一次，就是它前端有一个控制器。”
这是错的。

正确答法：是单例。
“Spring 容器的 Bean 默认作用域就是 singleton，@Controller、@RestController 都一样，整个容器只有一个实例。它之所以看起来像每次都是新的，是因为它无状态——每个请求的数据都在方法参数和局部变量里，不往成员变量里放，所以一个实例并发处理一万个请求也不冲突。
request、session、application、websocket 这几个作用域是 Spring MVC 额外提供的，必须显式用 @Scope 声明才有，不会默认生效。
真正要担心的是另一件事：如果 Controller 里放了会被改写的成员变量，比如 private int count，单例下就有线程安全问题。但正确的解法不是改成 prototype，而是别在 Controller 里放可变状态；真要存状态就用方法局部变量、ThreadLocal，或者显式声明 @Scope(“prototype”)，代价是每次请求新建一个对象。”

一句话答法：**”默认是单例的，所以我在 Controller 里不放可变的成员变量。要用 request 作用域得显式加 @Scope。”**

（注：prototype 的正式叫法是”原型”，不是”多实例”。术语用错会显得是背的。）

② AOP 的通知类型

面试官问的：我们说那个 AOP 它的通知类型都有哪些，你也了解过吗？

我当时答的：”有运行前那个前置通知……前置通知和后通知。其实这一块我记得不是特别清楚。”
面试官当场提示：**”最重要的其实还有一个是那个环绕通知。”**

正确答法：五种，按顺序说全——

注解 名称 什么时候执行
@Before 前置通知 目标方法执行之前，拿不到返回值
@AfterReturning 返回通知 目标方法正常返回后，用 returning 属性拿返回值
@AfterThrowing 异常通知 目标方法抛异常后，用 throwing 属性拿异常
@After 最终通知 不管正常还是异常都执行，等价 finally
@Around 环绕通知 把目标方法整个包起来，功能最强

环绕为什么最强：它的参数是 ProceedingJoinPoint，比其它四种多出来的能力有——能决定目标方法要不要执行（不调 proceed 就等于拦掉了）、能改参数（getArgs 拿出来改完传回 proceed）、能改返回值、能捕异常甚至重复执行。正因为返回值能被替换，环绕通知的方法返回值类型必须写成 Object，不能写死成具体类型。

顺带一句加分的：**@Transactional 底层就是环绕通知**——它靠 TransactionInterceptor（本质是一个 MethodInterceptor，也就是环绕增强）在方法前后开启事务和提交回滚。把 AOP 和事务串起来讲，比单答 AOP 好。

③ MySQL 的事务隔离级别

面试官问的：它的数的隔离级别有哪些？你知道吗？有你知道有几个吗？

我当时答的：”有四个的，一个是可重复读，一个是不可重复读。”
问题：把”不可重复读”这个问题当成了一个级别。面试官提示了两次、等了很久我才勉强凑出来。

正确答法：四个级别从低到高，别把问题当级别——

隔离级别 脏读 不可重复读 幻读
读未提交 会 会 会
读已提交 不会 会 会
可重复读 ← MySQL 默认 不会 不会 InnoDB 基本不会
串行化 不会 不会 不会

三个”问题”的定义，一句话一个，说得干脆：

  • 脏读：读到了别人还没提交的数据，别人一回滚，我读到的就是假的。
  • 不可重复读：同一个事务里两次读同一行，结果不一样（别人在中间 update 并提交了）。
  • 幻读：同一个事务里两次范围查询，第二次多出来几行（别人在中间 insert 并提交了）。

后两个最容易混，一句话区分：不可重复读管的是”这一行的值变了”，幻读管的是”多了几行”。

两个必须主动说的点：第一，MySQL InnoDB 默认是可重复读，这是它的特点；Oracle 和 PostgreSQL 默认都是读已提交（这家公司用的就是 PostgreSQL，说出来就是加分）。第二，可重复读下幻读怎么解决——快照读（普通 select）走 MVCC 读事务开始时的快照，看不到新插入的行；当前读（select for update、update、delete）走 next-key lock，把范围锁住不让别人在间隙里插入。

④ Linux 命令

面试官问的：你对这个 Linux 操作有了解吗？随便说几个基础命令吧，我听听。

我当时答的：”ls，最最简单的有 echo……ls -l 按照格式输出，或者 rm、remove，还有一些命令符号吧，像是 dollar 符或者那个横杠，或者 -r -f 这些。”
问题：说的是散点，还把 -r -f 这种参数当成了命令，听起来像没用过。

正确答法：按场景分组，别背散点——

  • 看目录和文件：ls -lh（-l 长格式、-h 人类可读、-a 含隐藏）、cd、pwd、mkdir -p
  • 看文件内容：cat、less（大文件能上下翻）、tail -f（跟日志，服务器上第一常用）、head、wc -l
  • 搜：grep -rn "关键字" .（递归＋行号）、find / -name "*.log"、which java
  • 权限：chmod 755 / chmod +x、chown 用户:组
  • 磁盘内存：df -h（服务莫名挂了先看这个）、du -sh *（逐层找哪个目录大）、free -h、top
  • 进程网络：ps -ef | grep java（找 Java 进程最常用）、kill -9 进程号、ss -tunlp（看端口被谁占用）、curl
  • 压缩传输：tar -zxvf、tar -zcvf、scp 文件 用户@主机:/路径
  • 服务：systemctl start/stop/status 服务名、journalctl -u 服务名 -f、nohup java -jar xx.jar &

加分答法：串成一个排障场景——
“我不单独背命令，我按’排查一个服务起不来’怎么走来记：先 ps -ef | grep java 看进程在不在；不在就 tail -f 看日志；如果是端口冲突，就 ss -tunlp | grep 8080 看谁占了；如果是磁盘满了写不进去，先 df -h 看整体，再 du -sh * 逐层找是哪个目录大；要在项目里搜配置或错误信息，就用 grep -rn。”

⑤ PostgreSQL 和国产数据库

面试官当时说的：”因为我们这个公司是面向政府单位的，像政府单位现在有很多比较有私密性的，确实不能用国外的，用的都是国产的，包括很多都准备国产化什么的。””不过没事儿，这个后续可以再学的，而且跟 MySQL 也差别不大其实。”
（他还说了一句底线：**”包括像一些数据，你要去问 AI 的话，这些都是不允许的。”**）

我当时答的：”国产的对我还我还真真不是特别了解这些。”——这题是当场能接住的，可惜没接。

正确答法：三段——承认 + 给差别 + 说迁移成本。

“PostgreSQL 我没有实际用过，不过它和 MySQL 的几个主要差别我知道：
第一，默认隔离级别不一样，PostgreSQL 是读已提交，MySQL 的 InnoDB 默认可重复读；
第二，PostgreSQL 对 SQL 标准的支持更完整，窗口函数、CTE、递归查询、JSON 和 JSONB 类型、数组类型，这些在 PG 里是一等公民，MySQL 这几年才慢慢跟上；
第三，索引类型更丰富，PG 除了 B-tree 还有 Hash、GiST、GIN、BRIN，MySQL 主要就是 B+ 树、哈希和全文索引；
第四，存储引擎，MySQL 有 InnoDB、MyISAM 多个可选，PG 只有一种堆表结构；
第五，有一个实际的坑：PG 默认把表名和列名转成小写，要用驼峰得加双引号。

① ★ 缓存过期机制有哪些（这场最大的崩点）

原话对话

面试官：应该是叫缓存过期怎么配置的？缓存过期机制有哪些？
我：有嗯我可能我想一下好吗……好像第一个是直接会抛出异常，然后……
面试官：第二个是策略抛出异常什么什么鬼？
面试官：那不是结果吗？超出所有的策略不都是超出不在策略内就会报异常吗？而且缓存缓存淘汰跟异常有啥关系啊？
我：那我可能对这一方面不是特别了解。
面试官：淘汰你这个再看看吧。

我错了三处：把”过期键删除策略”和”内存淘汰策略”当成同一个东西、一条具体策略名都说不出、编了一个”抛异常”。

正确答法：这是两个不同的机制，我分开说。

第一个：过期键删除策略（key 到点了怎么删）。Redis 用的是惰性删除 + 定期删除的组合。

  • 惰性删除：key 到期之后不主动删，等下一次有请求访问到这个 key 的时候，才检查它是否过期，过期就删掉并返回 nil。好处是对 CPU 友好，没被访问的 key 不浪费 CPU；坏处是如果这个 key 再也没人访问，它就会一直占着内存。
  • 定期删除：Redis 默认每 100 毫秒（配置项 hz，默认 10，也就是每秒 10 次）执行一次，每次从设置了过期时间的 key 里随机抽 20 个，把其中已过期的删掉。如果这一轮抽出来的样本里，过期 key 的比例超过 25%，说明过期 key 还很密集，就立刻再来一轮，直到比例降下来；整个过程有执行时间上限（一个周期内不超过 25 毫秒），到点就停，避免阻塞主线程。
  • 为什么要两个一起用：惰性删除保证”访问时一定是准的”、对 CPU 友好，定期删除保证”没人访问的过期 key 也能被清掉”、对内存友好。两者互补，是对 CPU 和内存的折中。

第二个：内存淘汰策略（内存满了怎么腾地方）。触发条件是 used_memory 达到 maxmemory 之后，每执行一条命令都会尝试淘汰。

默认是 noeviction：不淘汰任何 key，所有写命令直接返回错误 OOM command not allowed when used memory > 'maxmemory'，读命令还能正常用。
——我当时说的”抛异常”，来源大概就是这个报错。但那是写命令执行失败报错，不是”淘汰策略本身抛异常”。这个区别必须说清楚，不然听起来就是没懂。

一共 8 种，分两族：

族 策略 淘汰范围
allkeys allkeys-lru / allkeys-lfu / allkeys-random 在所有 key 里挑，lru 挑最久没被访问的，lfu 挑访问频率最低的，random 随机
volatile volatile-lru / volatile-lfu / volatile-random / volatile-ttl 只在设置了过期时间的 key 里挑，volatile-ttl 挑快要过期的
不淘汰 noeviction 默认值，内存满了写命令直接报错

LRU 看”最近有没有被访问过”，LFU 看”被访问的频率”，LFU 解决的是”偶尔被扫一次的冷数据把热数据挤掉”的问题。
补一个容易加分的细节：Redis 的 LRU 不是真正的 LRU，是近似 LRU——它不维护完整的访问链表（那要多占内存），而是随机采样 5 个 key 比一下谁最久没被访问，淘汰它，准确率够用。

项目里怎么选（追问必到）：”我这个 Redis 实例只做缓存，所以生产上会把 maxmemory-policy 改成 allkeys-lru。如果实例里混着不能丢的数据——比如我存的会话 token——就用 volatile-lru，同时保证所有缓存 key 都设了过期时间，绝不能让它去淘汰没设过期时间的 key。默认的 noeviction 做缓存是不能上生产的：内存一满，所有写请求全部失败。”

一分钟版本（背这个）

“这是两个不同的机制，我分开说。
过期键删除是 key 到点了怎么删，Redis 用惰性删除加定期删除。惰性删除是访问到才检查、才删，对 CPU 友好，但没人访问的过期 key 会一直占内存；定期删除是每 100 毫秒随机抽 20 个设了过期时间的 key，过期比例超过 25% 就再来一轮，有 25 毫秒的时间上限，防止阻塞主线程。两个互补。
内存淘汰是内存到 maxmemory 了怎么腾地方，一共 8 种，默认是 noeviction，也就是不淘汰、写命令直接报 OOM 错误。剩下 7 种分两族：allkeys 开头的在所有 key 里挑，volatile 开头的只在设了过期时间的 key 里挑；挑法又分 LRU、LFU、random，volatile-ttl 是挑快过期的。Redis 的 LRU 是近似 LRU，随机采样 5 个比时间戳。
我这个 Redis 只做缓存，所以生产上会配 allkeys-lru；如果混了不能丢的数据，就用 volatile-lru 并且保证缓存 key 都设了过期时间。”

② HyperLogLog 的底层原理

面试官问的：HyperLogLog 是干嘛的？→ 从哪了解到的？→ 底层实现原理知道吗？

我当时答的：”是用它是一种用来去重的 user view 的一种工具好像是一种工具类吧，它能够对用户访问帖子的次数进行去重。”追问原理：”并不了解。”
问题：只说了它是”干什么用的”，原理一个字没有。面试官连问三级（干什么 → 从哪学的 → 底层原理），这就是标准的”戳穿背诵”路径。

正确答法：先说它解决什么，再说原理，再说误差和空间。

“HyperLogLog 解决的是基数统计，也就是估算一个集合里有多少个不重复元素。注意它不是去重，也不是判断某个元素在不在，它只回答一个问题：大概有多少个不同的元素，而且是概率算法，结果有误差。

原理来自伯努利实验：抛硬币，记录’第一次抛出正面时一共抛了几次’。这个次数越大，说明试的次数越多；反过来，如果记录到的最大值是 k，就能反推实验次数大概是 2 的 k 次方。

具体到算法里：把每个元素哈希成一个 64 位串，用低 14 位决定放进哪个桶——所以有 2 的 14 次方等于 16384 个桶；用剩下位里第一个 1 出现的位置（也就是前导零个数加一）作为这个桶的 k 值；每个桶只存自己见过的最大值。
估算总数的时候，16384 个桶的值取调和平均数——不是算术平均，因为算术平均很容易被一个极端大的值带偏，调和平均对异常值不敏感——再乘一个修正常数。

误差是算出来的：理论标准误差大约是 1.04 除以根号 16384，约等于 0.81%。
内存是每个桶 6 bit，16384 乘 6 bit 等于 12KB，固定 12KB，跟元素个数完全无关——这才是它相对 Set 的全部意义，一百万个 UV 用 Set 存字符串要几十 MB。

边界我说清楚：它只能算数量，不能判断某个元素在不在（那个要用布隆过滤器），也不能把原始元素取回来。PV 就直接用 INCR 累加，不需要它。”

③ Redis 分布式锁的原理

面试官问的：Redis 分布式锁了解吗？给我讲原理。

我当时答的：”是 redis 做中间层，然后用 sent nx 这个指令设置过期时间，然后去通过缓存拿到这把锁去访问数据库。”
问题：这只是用法，不是原理。而且”sent nx”是术语读错（是 SETNX）。

正确答法：按六步讲——

  1. 加锁：SET lockKey 唯一值 NX EX 10。NX 保证 key 不存在才设置（互斥），EX 带过期时间（防死锁），两条合在一条命令里是原子的。对比一下：如果先 SETNX 再 EXPIRE，中间崩了就是一把永不过期的锁。
  2. value 必须是唯一值（比如 UUID 或”机器 ID 加线程 ID”）：解锁的时候要先判断这把锁是不是自己的，不然可能删掉别人的锁——我超时了，醒来直接把别人刚拿到的锁删了。
  3. 解锁必须用 Lua 保证原子：先 GET 出来比对 value，相等才 DEL。这两步如果分开做，比对完到自己删除之间锁可能刚好过期被别人拿到，还是删错。
  4. 锁过期了但业务没做完怎么办：这是 SETNX 方案绕不过去的洞。Redisson 的解法是看门狗——加锁成功后起一个后台定时任务，每隔锁过期时间的三分之一给锁续期，业务线程结束的时候主动取消续期（默认锁 30 秒，每 10 秒续一次）。
  5. 可重入：同一个线程再次加锁应该成功并且计数加一，Redisson 用 Hash 结构存”线程标识到重入次数”来实现。
  6. 已知的边界（主动说，加分）：主从切换时会丢锁——主节点加锁成功还没同步到从节点就挂了，从节点升主之后锁就没了。这个要提一句 RedLock（同时向多个独立 Redis 实例加锁、多数成功才算拿到）或者用 etcd、ZooKeeper 这类共识组件。

④ 随机 TTL 是干什么的

面试官问的：我看你这边也有随机 TTL，你还做了 TTL 配置。

我当时答的：”它就是一个随机偏移量嘛。”——只说了是什么，没说为什么。

正确答法：一定要带上它解决的问题——
“这是为了防缓存雪崩。很多 key 如果都在同一时间过期，那一刻所有请求会一起漏到数据库上，数据库直接被打崩。所以在过期时间上加一个随机偏移量，基础十分钟再加零到五分钟的随机数，把过期时间打散，不要挤在一起。”

面试官问的：切面有了解过吗？→ 环绕切面里面有哪些方法？一共有三个方法，哪三个方法？

⑥ Docker 常用命令（★ 杀伤力最大的一处）

面试官问的：你给我讲讲 Docker 有哪些指令？→ Docker image 是干嘛的？→ Docker ps 是干嘛的？

我当时答的：”嗯，它主要是配置吧。””还是借用 AI 借的多。”然后三连问全部答不上来，最后说”行，有点有点答不上来。”
为什么致命：简历上写着”Docker + Compose 部署到阿里云”，结果连 docker ps 都答不出——面试官就是用这个判断”你是照着视频抄的”。这一处直接毁掉了整份简历的可信度。

正确答法：命令一共十几个，按三组背。

第一组：镜像（镜像是模板，只读分层）

  • docker images（或 docker image ls）—— 列出本地所有镜像，能看到仓库名、标签、镜像 ID、大小
  • docker pull nginx:1.25 —— 从仓库拉取镜像，要带标签，别用 latest
  • docker build -t 应用名:1.0.0 . —— 按当前目录的 Dockerfile 构建镜像，-t 打名字和标签
  • docker rmi 镜像ID —— 删除镜像
  • docker history 镜像ID —— 看这个镜像每一层怎么来的（排查为什么这么大时好用）

第二组：容器（容器是镜像跑起来的实例，在镜像上加一个可写层）

  • docker ps —— 看正在运行的容器，能看到容器 ID、镜像、启动命令、状态、端口映射、名字
  • docker ps -a —— 看所有容器，包括已经退出的。这两个的区别是问得最多的：ps 只看 Up 的，ps -a 连 Exited 的一起看。容器起不来第一件事就是 docker ps -a，看它是不是启动完就退出了
  • docker run -d --name 应用名 -p 8080:8080 镜像名:标签 —— 跑一个容器。-d 后台运行；--name 起名字；-p 8080:8080 端口映射，冒号左边是宿主机端口，右边是容器里的端口；-v /宿主目录:/容器目录 挂载数据卷；-e KEY=VALUE 传环境变量
  • docker start / stop / restart 容器名 —— 启停重启
  • docker rm 容器名 —— 删除容器（-f 强删正在跑的）
  • docker exec -it 容器名 bash —— 进容器里开一个交互式终端排查。-i 保持标准输入打开，-t 分配一个伪终端
  • docker logs -f 容器名 —— 跟日志，排查线上问题第一命令
  • docker inspect 容器名 —— 看容器详情（IP、挂载、环境变量、健康状态）

第三组：Compose（我项目里用的就是这个）

  • docker compose up -d —— 按 docker-compose.yml 一键起全部服务，加 --build 会先重新构建
  • docker compose ps —— 看这个编排里所有服务的状态（我项目里最常用的就是这条）
  • docker compose logs -f 服务名 —— 跟某个服务的日志
  • docker compose down —— 停止并删除所有容器和网络（数据卷默认不删，所以数据还在；加 -v 才会连卷一起删）
  • docker compose restart / stop / start 服务名、docker compose build

几个高频追问一起背掉：

  • 镜像和容器的区别：镜像是只读的模板（一层层叠加的分层文件系统），容器是镜像跑起来的实例，在镜像最上面加了一个可写层。一个镜像可以跑出很多个容器。
  • -p 8080:8080 冒号两边是什么：左边宿主机，右边容器。
  • 为什么不用进容器看日志文件：应用日志打到标准输出，Docker 会收集，docker logs 直接看就行。
  • COPY 和 ADD 的区别：ADD 支持自动解压压缩包和从 URL 下载，COPY 只做复制，一般用 COPY。
  • Dockerfile 里为什么先 COPY pom 再 COPY 源码：为了利用层缓存，改代码时不用重新下载依赖（这条我项目里真做了，可以讲）。

⑦ Java 泛型

面试官问的：Java 的泛型有没有了解过？Java 源码有看过吗，里面经常会有什么 T、问号。

我当时答的：”有的它主要是为了做一个约束嘛，可以指定它接收的参数的类型，还有一个就是那个 extend 的关键字……好像是 T, extends 1 个嗯 number 的类吧，好像是 number。”
问题：意思沾边了，但一个术语都没说准。

正确答法：按”是什么 → 三种写法 → 上下界 → 类型擦除”讲。

“泛型就是把类型也当成参数传。好处有两个：编译期就能发现类型错误（而不是等到运行期抛 ClassCastException），以及省掉强制类型转换。
写法有三种：泛型类 class Result<T>、泛型方法 public <T> T get(Class<T> clazz)、泛型接口 interface BaseMapper<T>。类型参数 T、E、K、V 都只是约定，不是关键字，T 是 Type、E 是 Element、K 和 V 是 Key 和 Value、问号是通配符。

上下界：List<? extends Number> 是上界，只能读，读出来能当 Number 用，不能写（除了 null）——因为编译器不知道它到底是 List<Integer> 还是 List<Double>，写进去会破坏类型安全；List<? super Integer> 是下界，可以往里写 Integer，但读出来只能当 Object。记法就是 PECS：Producer Extends, Consumer Super，你要从里面读就用 extends，要往里面写就用 super。

最关键的是类型擦除：泛型只在编译期存在，编译完之后所有泛型信息都会被擦掉——无界的 T 擦成 Object，T extends Number 擦成 Number，运行时的 JVM 里根本没有泛型这个概念。这一条能解释一串看起来很奇怪的限制：不能 new T[]、不能 new ArrayList<T>()（运行时不知道 T 是什么）；不能 instanceof List<String>；静态方法里不能用类的类型参数；泛型不支持基本类型，所以 List<int> 是错的，必须用包装类 List<Integer>。

项目里用得最多的是集合和统一返回体，比如 Result<T> 包 OrderVO，还有 MyBatis-Plus 的 BaseMapper、Feign 的接口返回值。”

⑧ 数据结构与算法

面试官问的：数据结构算法，大学学的怎么样？

我当时答的：”有这类的课程，但是可以问吗？我只接触过 java 的集合。”面试官说”我说数据结构算法跟 java 没关系”，我答**”那算法嗯没有”**。
问题：答”没有”是最伤的一种答法——它同时否定了课程、自学和意愿。

正确答法：承认是短板，但当场把会的那部分说清楚，别把天聊死。

“这块是我目前的短板，我说实话。
数据结构本身我能讲清楚——数组、链表、栈和队列、哈希表，树里面二叉搜索树、红黑树和 B+ 树的区别，以及 B+ 树为什么适合做索引。排序我熟悉快排和归并的思想，也能说出它们的时间复杂度和稳定性。
算法题我在补，目前在刷 LeetCode，主要做数组、字符串、链表、双指针和二叉树这一类，简单和中等难度为主。
我现在能把链表反转、二分查找、有效的括号这几道白板写出来。”

（最后一句必须是真话。还没刷就先去做，别吹。）

要能答的基础：

  • 时间复杂度：O(1) < O(logN) < O(n) < O(nlogN) < O(n²)，各举一例——哈希查找 O(1)、二分 O(logN)、快排和归并 O(nlogN)、冒泡 O(n²)。
  • 快排：选基准，小的放左边大的放右边，两边递归；平均 O(nlogN)，最坏 O(n²)（基准选得极端，退化成冒泡），原地、不稳定。
  • 归并：分两半各自排好再合并；稳定，O(nlogN)，但要额外 O(n) 空间。
  • 数据结构各自解决什么：数组（随机访问快、增删慢）、链表（增删快、随机访问慢）、栈（后进先出，括号匹配、函数调用）、队列（先进先出，任务排队）、哈希表（O(1) 查找）、树（二叉搜索树、红黑树、B+ 树）、堆（求 Top K）、图（最短路、拓扑排序）。
  • 最可能被要求手写的：链表反转、快慢指针判环、二分查找、两数之和、有效的括号（栈）、合并两个有序链表。

⑨ “是不是看了视频照着写的？”

面试官问的：”我问一下你现在做这个项目，是不是因为看到了这样一个视频，然后视频里面给你讲了这样一个逻辑，你想去实现一下？””我想看的是脱离视频，比如没人跟你讲，你有没有做什么什么事情然后学到了什么。”

我当时答的：”是不是啊？是的。”然后想说”项目的上线算吗”，但已经晚了。
问题：面试官问这句不是要否定你，他是在给你一个证明自己的机会——“你说点视频里没有的东西给我听”。只答”是的”就把机会丢掉了。怎么接见 四·4.2。

四、应对方法

4.1 答不出来时怎么救（三招）

  1. 复述问题争取时间：”您问的是 XX 这块，对吧？”——重复一遍问题，脑子就有三秒组织语言。
  2. 先给结论再补细节：哪怕细节想不起来，先把结论说出来。”这块我用的方案是 A，具体实现上……”结论对了，细节磕巴不算大问题；反过来细节讲了一堆但没结论，面试官会认为你没抓住重点。
  3. 主动换战场：某个点实在讲不深，就诚实说”这块我了解得比较浅，我只知道 X”，然后立刻转去你熟的。”不过在那之前，我用过一个类似的方案是 Y，我详细说一下。”不要在一个坑里硬撑。

但有一条线不能越：绝对不要编。三面那个”缓存过期就是抛异常”就是编出来的，面试官一句”缓存淘汰跟异常有啥关系”就把它戳穿了，而且塌的不是这一题，是整场的可信度。不会就说不会，然后把你确定的那部分讲清楚。

4.2 被质疑”照着视频抄”怎么答

三步：承认起点 → 摆出增量 → 主动交代已修复的短板。

“面试官，这个我不回避，这两个项目的起点确实是跟着教程和视频学的，第一个项目的原型就是照着做的。但有三件事是教程里没有的：

第一，教程里用的是 XX，我改成了 YY，因为……（必须准备一个真实的例子，这是整段话的支点）。

第二，整套部署链路——Docker 打包、Compose 编排、nginx 反代、到服务器上真正跑起来——是我自己一步步试出来的，中间踩的坑我能讲，比如 MySQL 容器起来了但还在初始化，后端连上去就报错，后来加了 healthcheck 控制启动顺序。

第三，也是我要坦白的：我上一场面试被问倒过几个基础题，Redis 的过期删除和内存淘汰我混在一起了，Docker 的基础命令我当场答不出来。回去之后我补了，现在可以讲清楚——（然后当场流利地讲 30 秒）。

所以您说的’先盖地基’我认同，我现在正在补的就是这一层。”

这段的关键在第三点。主动说出”我上一场被问倒、我回去补了”，比任何辩解都有说服力——它同时证明了我会复盘、能自学、不装。而当场把那 30 秒讲流畅，就把”抄的”这个质疑变成了”这人学得进去”。

可以当场说的增量素材（都是真的）：

  • 部署链路是自己走通的（Docker 多阶段构建、Compose healthcheck 控制启动顺序、nginx 的 SPA 回退、公网 IP 访问）——这些都是视频里不会细讲的。
  • 踩过的坑（MySQL 容器起来了但还在初始化、后端连不上一直重启；nginx 的 proxy_pass 带不带斜杠的区别）。
  • 主动的取舍（库存重建时不覆盖实时库存、Feed 流为什么选推模式、大 V 场景的边界）。
  • 已知的不足（缓存删失败没有重试、草稿转单还没挂全局事务）。

最有力的一句（练熟它）：

“视频教的是怎么把这套东西跑起来，但从跑起来到讲清楚它为什么这么设计、它在什么情况下会出问题，中间那一段是我自己补的。比如秒杀那段 Lua，我一开始用的不是 Lua，是分开两条命令，后来我想明白中间有窗口会超卖，才改成 Lua；再比如 Redis 重启之后库存 key 会丢，我加了数据库的联合唯一索引兜底，但我知道这只防得住一人多单，防不住重启后的超卖，那个要用对账任务，我没做。”

4.3 表达上必须改的四个毛病

  1. 掐掉语气词：嗯、那个、然后、就、嘛。录音里数一下，一个”嗯”就是一次走神。
  2. 先给结论，再分点展开。用”我分三层说””第一、第二、第三”组织，不要想到哪说到哪。
  3. 术语必须准确。术语错一次，技术可信度就掉一档。对照表见 4.4。
  4. 不要报没有背书的数字。面试官一句”你压测用的什么工具”就能戳穿。

4.4 术语对照表

我说错的 正确的是
1000 到 2000 的 kps QPS（kps 这个说法不存在）
sent nx SETNX，或者直接说 SET key value NX EX
布隆缓存器 布隆过滤器
being denied a definition BeanDefinition
面向千编程 面向切面编程（AOP）
JDK 代理写成”gdk”、CGLIB 写成”gc lib” JDK 动态代理、CGLIB
多实例 单例 / 原型（prototype）
缓存淘汰”会抛出异常” 过期键删除（惰性 + 定期）/ 内存淘汰（8 种，默认 noeviction，写命令报 OOM）

4.5 简历要调的地方

不是造假，是重排和补实。

  1. 技能栏第一条改成 Java 基础（集合 / 并发 / JVM / 泛型 / IO），第二条数据结构与算法，第三条 MySQL 和 Redis，第四条才是 Spring / Spring Boot，第五条 Spring Cloud Alibaba，第六条工具链（Docker / Linux / Git / Maven）。会什么写什么，不会的删掉。
  2. 每个中间件后面写”我做了什么”，不写”我用过什么”。 不是”熟悉 RabbitMQ”，而是”用 RabbitMQ 的延迟消息做 30 分钟自动关单，用唯一键加状态机保证消费幂等”。写得越具体越不像抄的——抄的人写不出细节。
  3. **项目里加一条”已知不足与取舍”**，比如”Redis 与数据库的库存一致性目前只做了功能层面验证，还没做对账任务”。主动列不足是”真做过”最强的信号。
  4. 能拿出来的”真写过”的证据都放上：Git 提交记录、刷题数量、代码行数。git log 是最难伪造的东西。
  5. “网关双 token”这个说法改掉，改成”网关多身份鉴权（admin / user 双套 JWT）”。二面面试官就把它误解成了 access token 加 refresh token 那种双 token。
  6. 凡是简历上写了的工具，命令必须能张口。 写了 Docker 部署，就得答得出 docker ps。这是三面翻车最狠的地方。

4.6 不要再做的四件事

  1. 不要再报任何没有压测背书的数据（”QPS 5200+”这类）。
  2. 不要再把”前后端都是我自己做的”和”Docker 命令答不上来”放在同一场里——这是自相矛盾。
  3. 被问 AI 占比不要含糊。前端 AI 辅助多，后端核心链路自己设计，哪个模块 AI 帮的直接说。
  4. 不要编没做过的细节。面试官一追就塌，塌的是整场的可信度。

4.7 面试当天的准备

  • 提前吃东西，兜里备糖。 二面我低血糖发作，中途要停下来组织语言，面试官虽然宽容，但这是白白丢分。
  • 带一份打印的简历，面试官对着问的时候你能跟着看。
  • 进门前想一遍这五个：① 项目亮点先认定位再讲四个钩子 ② AI 占比说七成自研 ③ 秒杀流程顺序不能反 ④ 术语用准 ⑤ 掐掉语气词。

五、进门前速览

三场一共 21 道没答好的题，按场次列在这，能全部脱稿讲出来才算过。

一面 · 礼芮行（7 道）

  • ☐ 秒杀系统怎么实现的（Lua 四步：查 key 在不在 → 读库存 → SETNX 一人一单 → 库存减一）
  • ☐ 唯一索引根据哪两列（活动 ID 加用户 ID，语义是”这个人在这个活动里的那一单”）
  • ☐ Bean 生命周期顺序（注册 BeanDefinition → 实例化 → 属性填充 → Aware → 后置处理器前后置 → init → 使用 → 销毁）
  • ☐ MySQL 能力（索引 / 事务 / 项目落点三块，别只说 MyBatis Plus）
  • ☐ 能扛多少并发（只报 20 并发 0 超卖，说明是功能验证不是性能验证）
  • ☐ AI 占比（前端辅助多、后端七成自研、核心链路自己设计）
  • ☐ 两个项目名 + 1 分钟版 / 3 分钟版

二面 · 上海熙宽（6 道）

  • ☐ AOP 五种通知 + 环绕通知三个方法（proceed / getArgs / getSignature）
  • ☐ MySQL 四个隔离级别 + 三个问题 + 默认可重复读 + 幻读怎么解决
  • ☐ Linux 命令（按场景分组 + 串一个排障场景）
  • ☐ PostgreSQL 与国产数据库（五条差别 + 国产库血统 + 迁移成本）
  • ☐ Java 8 新特性（Lambda / Stream / Optional / 默认方法 / 新日期 API / 红黑树 / 元空间）

三面 · 昆山小哈机电（8 道）

  • ☐ ★ 缓存过期机制（过期键删除：惰性 + 定期；内存淘汰：8 种，默认 noeviction）—— 这条最该先背
  • ☐ HyperLogLog 原理（16384 桶、前导零、调和平均、0.81%、12KB）
  • ☐ Redis 分布式锁原理（六步：NX+EX 原子、value 唯一标识、Lua 释放、看门狗、可重入、主从丢锁）
  • ☐ 随机 TTL 为什么（防雪崩）
  • ☐ 环绕通知有哪些方法
  • ☐ Docker 三组命令（镜像 / 容器 / Compose，ps 和 ps -a 的区别）
  • ☐ Java 泛型（类型参数、上下界、PECS、类型擦除）
  • ☐ 算法（承认短板 + 说清进度 + 当场展示会的那部分）

四个应对动作

  • ☐ 答不出来：复述问题拖时间 → 先给结论 → 主动换战场，但绝不编
  • ☐ 被质疑照着视频抄：承认起点 → 摆出增量 → 主动交代已补的洞
